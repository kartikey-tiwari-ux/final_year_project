# Modality Conflict Analysis

Real statistics computed from `results/test_predictions.csv` (450 test samples, the
same held-out split used for every model's headline metrics — see
`DATASET_SELECTION.md` / `REPRODUCIBILITY.md`). Generated by
`src/evaluation/generate_predictions.py`; Model C here is the concat-fusion model
(`src/multimodal/fusion_concat.py`), using the exact same trained weights/training
procedure as its headline result (64.44% test accuracy) — not a re-approximation (an
earlier inconsistent re-approximation was caught and fixed; see `REPRODUCIBILITY.md`).

## 1. How often do text and image disagree?

| | Count | % of test set |
|---|---|---|
| Text (A2) and Image (B2) predict the **same** class | 210 | 46.7% |
| Text (A2) and Image (B2) predict **different** classes | 240 | 53.3% |

More than half the time, the text-only and image-only models land on different
sentiment predictions for the same post — confirming the project's founding premise
(synopsis Ch. 1.1.2): text and image frequently carry non-identical signal, so how a
multimodal model handles that disagreement matters.

## 2. Does fusion help specifically on the disagreement subset?

| Model | Accuracy on the 240 disagreement samples |
|---|---|
| Text only (A2) | 50.0% |
| Image only (B2) | 33.3% |
| **Fusion (C)** | **57.1%** |

On exactly the samples where the two modalities conflict — the hard cases fusion
exists to help with — the fusion model clearly outperforms either unimodal model
alone (+7.1pp over text, +23.8pp over image). This is the clearest, most direct
evidence in this project that combining modalities helps: not just on average, but
specifically *when there is something for fusion to resolve*.

## 3. Does fusion ever hurt when the modalities already agree?

| | Accuracy |
|---|---|
| Text (A2) on the 210 agreement samples | 74.8% |
| Fusion (C) on the 210 agreement samples | 72.9% |

A small (1.9pp) regression — when text and image already agree, text alone is
slightly *more* accurate than the fusion model on this subset. This is reported as-is,
not smoothed over: fusion is not a free, unconditional win; its value concentrates on
the disagreement cases (§2), and it has a small cost on the agreement cases.

Breaking the agreement subset down further:
- **Both unimodal models agree and are correct** (157 samples): fusion preserves
  correctness 91.7% of the time (a small number of cases where fusion overrides two
  correct unimodal signals into a wrong prediction).
- **Both unimodal models agree and are both wrong** (53 samples): fusion only
  corrects 17.0% of these. This makes sense — if both modalities independently point
  to the same wrong answer, there is little signal left for a fusion model trained on
  the same two modalities to find the right one; this is a real limitation, not a
  failure of the fusion method specifically.

## 4. Net effect: does fusion fix more than it breaks?

| | Count | Fusion's effect |
|---|---|---|
| Text (A2) wrong (173 samples) | fusion fixes 68 | **39.3%** of text's errors corrected |
| Text (A2) right (277 samples) | fusion breaks 55 | **19.9%** of text's correct predictions overturned |

Net: fusion fixes 68 and breaks 55, a net gain of +13 correct predictions out of 450
(matching the headline accuracy gap: 64.4% − 61.6% ≈ 2.9pp ≈ 13/450). The gain is real
but modest, and comes with a genuine cost (fusion does make some previously-correct
text predictions worse) — both sides of this trade are reported, not just the gain.

## 5. Per-class breakdown — where fusion helps and where it doesn't

| Class (test n) | Text (A2) | Image (B2) | Fusion (C) |
|---|---|---|---|
| positive (268) | 63.4% | 61.2% | **69.4%** |
| neutral (47) | 48.9% | 23.4% | 42.6% |
| negative (135) | 62.2% | 45.9% | 62.2% |

Fusion clearly helps on the majority class (positive, +6.0pp over text) but
**underperforms text-only on neutral** (42.6% vs 48.9%, −6.3pp) and is flat on
negative. Neutral is both the smallest class (47/450, matching the training set's
neutral scarcity — 376/3,611, see `DATASET_SELECTION.md`) and the hardest for every
model here; fusion does not fix this, and may make it slightly worse, plausibly
because the fusion head has the least neutral-class training signal to learn a
reliable joint decision boundary from. This is flagged as a limitation for
`RESEARCH_GAP.md` point 3 and the final report's limitations section, not minimized.

## 6. Qualitative examples (real test-set samples, from `results/qualitative_examples.txt`)

**Text wrong, fusion (aided by the image) got it right:**
- id=192, true=positive, text-only predicted negative: *"This doesn't even look like Kerry.. #appalled"* — the text alone reads negative ("appalled"), but the attached image apparently supplied enough positive visual signal for fusion to override it correctly.
- id=229, true=positive, text-only predicted negative: *"Baddieeee RT @1NA_Trillion: Beautifully Flawed"* — informal/ambiguous slang ("Baddieeee") likely confused the text model; fusion corrected it.

**Text right, fusion broke it:**
- id=220, true=positive, text-only correct, fusion→negative: *"RT @Paul_nevs: ... Thought you might like my image of a wolf I recently finished"* — neutral/descriptive text about a wolf photo; the image (a wolf) may have carried a visually "negative-coded" signal (e.g. a dark/intense photo) that overrode otherwise-correct text sentiment.
- id=537, true=positive, text-only correct, fusion→negative: *"@BestBergerEver @JoelTemperlane Katy and Bill ruined Valentine's for me because their love is too perfect."* — text contains "ruined," a negative-coded word used ironically/positively here; the fusion model may have been pulled toward negative by this lexical cue reinforced by the image, where the text-only model's broader context handled the irony correctly.

These examples illustrate a real, interpretable limitation: fusion can be pulled
toward an incorrect prediction when the image's visual sentiment signal conflicts with
subtle textual cues (sarcasm, ironic use of negative words) that the text-only model
handles correctly on its own.

## Conclusion

Multimodal fusion's benefit in this project is **real but concentrated**: it provides
a clear, substantial improvement specifically on posts where text and image disagree
(+7–24pp over the better/worse unimodal model on that subset), at a smaller cost on
posts where they already agree. It does not uniformly help every class — notably, it
underperforms text-only on the neutral class, the hardest and most data-scarce
category. This nuanced picture — not a blanket "multimodal wins" — is the honest
answer this project's central research question, consistent with the non-overclaiming
commitment in `RESEARCH_GAP.md` and `ORIGINALITY.md`.
